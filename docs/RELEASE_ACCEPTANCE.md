# 玉衡发布验收清单

本文用于区分**代码/CI 验证**与**真实设备验收**。勾选项必须有对应测试记录、Actions 运行或设备结果支撑；没有执行的项目保持未勾选，不得用“构建成功”代替功能通过。

## 1. 自动化验证

- [ ] `:app:testDebugUnitTest` 全部通过。
- [ ] `:app:lintDebug` 与 `:app:lintRelease` 无新增 Error / Fatal；历史技术债见 [LINT_DEBT.md](LINT_DEBT.md)。
- [ ] Debug APK 成功构建，产物包名为 `me.weishu.kernelsu.preview`。
- [ ] 正式 Release APK 成功构建，包名为 `me.weishu.kernelsu`。
- [ ] 正式 APK 使用预期签名证书；核对 APK v2 SHA-256 与 LKM 侧预期摘要一致。
- [ ] LKM 构建成功，并记录目标 KMI、架构、工具链和产物 SHA-256。
- [ ] Release APK 与 LKM 均来自同一轮经过核对的源码版本。

## 2. 安装、升级与启动

- [ ] 首次安装后可正常启动，无启动崩溃或持续卡加载。
- [ ] 相同签名的正式版本覆盖升级成功，应用数据与设置保留。
- [ ] Debug Preview 与正式包的包名、签名身份清晰区分，不发生错误覆盖。
- [ ] 横竖屏/窗口尺寸变化后页面状态正常。
- [ ] 强制停止并重新打开后，主题、昼夜模式和壁纸设置保持正确。

## 3. Root 与超级用户

> 仅在已备份、可恢复且确认匹配的测试设备上执行。

- [ ] 正确显示当前 Root / KernelSU 状态和版本信息。
- [ ] 新应用发起 Root 请求时，授权弹窗与请求方信息正确。
- [ ] 允许、拒绝、撤销授权后列表状态正确刷新。
- [ ] 授权记录在重启后符合预期。
- [ ] 无 Root 环境或不支持的内核环境下，页面明确展示不可用状态，不误报已获得 Root。

## 4. 模块管理

- [ ] 模块列表加载、空列表、加载失败状态均可理解。
- [ ] 搜索、筛选和模块详情显示正确。
- [ ] 从可信来源安装有效模块成功；无效/损坏包给出可理解错误。
- [ ] 启用、停用状态与底层实际状态一致。
- [ ] 卸载操作有明确确认，完成后列表正确刷新。
- [ ] 重启后模块状态与 KernelSU 实际状态一致。

## 5. 首发主题、显示与壁纸

> 首发可用主题为「青龙 · 苍璧」。主题选择界面同时保留白虎 · 霜华、玄武 · 玄甲、朱雀 · 丹曜、麒麟 · 紫宸四个未来主题入口，必须明确标注「待开发」、不可选中、不可改变当前主题。

- [ ] 青龙主题名称、苍青玉色、青龙识别元素与主题背景保持一致。
- [ ] 主题选择界面展示五神兽：青龙 · 苍璧可正常选择；白虎 · 霜华、玄武 · 玄甲、朱雀 · 丹曜、麒麟 · 紫宸均显示「待开发」且不可点击/不可应用。
- [ ] Material 与 Miuix 两种 UI 模式均使用青龙主题；切换 UI 模式不改变主题色、壁纸或深浅色设置。
- [ ] 两种 UI 模式的首页、超级用户、模块、设置四个导航入口及徽标行为一致。
- [ ] 两种 UI 模式均检查浅色、深色和跟随系统三种显示状态下的文字对比度、图标可见性和状态颜色。
- [ ] 悬浮底栏可独立开启/关闭；关闭时回退为完整、清晰的实体底栏，不出现透明空洞。
- [ ] 玻璃材质可独立开启/关闭；开启时检查背景透射、模糊、边缘层次，关闭时保留实体材质。
- [ ] 底栏不遮挡页面内容；系统手势区域、导航栏安全区和横竖屏布局正确。
- [ ] 通过系统文档选择器选择图片后，背景可正常显示，且自定义壁纸优先于青龙默认背景。
- [ ] 更换壁纸后旧 URI 授权被释放；恢复默认后回到青龙主题背景。
- [ ] 重启应用/设备后，持久化壁纸仍可读取。
- [ ] 图片被删除、提供方撤销权限、格式损坏或超大图时，应用不崩溃，并能恢复默认背景。
- [ ] 自定义壁纸在浅色/深色界面上均不影响正文、导航和控件可读性。

## 6. 设备适配与体验

- [ ] 小屏、大屏、系统字体放大时无关键内容遮挡或横向溢出。
- [ ] 底部导航不遮挡滚动内容，系统手势区域和安全区留白正确。
- [ ] 页面加载、空状态、错误状态、权限不足状态均有明确反馈。
- [ ] 主要可点击区域有足够尺寸，图标按钮具有无障碍描述。
- [ ] 连续切换页面和主题时无明显掉帧、异常内存增长或重复请求。

## 7. LKM 与签名安全

- [ ] 设备架构、内核版本、KMI 与 LKM 构建目标完全匹配。
- [ ] APK 签名摘要与 LKM 信任配置逐字节核对。
- [ ] 安装/更新前备份 boot/init_boot/vendor_boot 等相关启动镜像，并确认可恢复方案。
- [ ] 不在未经验证的设备上自动刷写或替换内核模块。
- [ ] 正式发布包不包含 keystore、私钥、密码、调试日志或个人数据。

## 8. 发布前记录

每次候选发布至少记录：

| 项目 | 记录 |
| --- | --- |
| 源码 commit | 待填写 |
| Android CI run | 待填写 |
| 单元测试 / Lint | 待填写 |
| APK 文件名与 SHA-256 | 待填写 |
| Application ID / versionName / versionCode | 待填写 |
| APK 签名证书 SHA-256 | 待填写 |
| LKM 文件名与 SHA-256 | 待填写 |
| 设备型号 / Android / 内核 / KMI | 待填写 |
| 真机回归结果与未解决问题 | 待填写 |

**发布原则：** 所有与目标发布形态相关的必测项通过后，才可标记为 Release Candidate。未完成的真机项必须明确列出；CI 通过、源码提交或 APK 生成本身都不等于正式版验收完成。
