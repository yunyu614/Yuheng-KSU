# 玉衡 V1.0 开发与发布计划

## 当前项目状态

项目处于持续开发阶段，尚未达到 Release Candidate，也没有正式 GitHub Release。开发主线为 develop。每次交付以对应提交的 GitHub Actions 结果和设备验收记录为准。

## 已集成的工程能力

以下项目表示代码或工作流已经集成，不代表已完成所有设备验证：

- 基于 KernelSU 上游管理器代码维护 Root、超级用户、模块和安装等核心管理链路；品牌与 UI 改动应避免改变底层授权协议。
- 玉衡品牌体系与五套主题色板数据已经建立；当前仅青龙 · 苍璧可用，白虎、玄武、朱雀、麒麟保留待开发状态。
- Material 与 Miuix 两套界面均接入主题体系，并提供昼夜模式、悬浮底栏和玻璃材质相关设置。
- 自定义壁纸有两条导入路径：设置页通过 OpenDocument 保存持久只读 URI；主题页校验大小与图像尺寸后复制到应用私有目录。两者使用同一 settings 偏好文件和 yuheng_wallpaper_uri / yuheng_wallpaper_file 键。
- Android Debug 预览构建、LKM 构建和手动签名 Release 工作流已存在；Release 工作流包含包名和 APK v2 证书摘要校验。
- README、变更记录、贡献指南、安全策略和发布验收清单已建立。

## 质量门槛

### 自动化

- 每次代码提交必须检查对应 Android 单元测试和 Debug APK 构建结果。
- Android Lint 继续执行并保存报告；历史翻译和依赖告警按技术债计划逐项处理，不通过关闭规则或隐藏报告伪装通过。
- Release 变体必须单独构建并验证 Application ID、版本信息、签名身份和 APK v2 证书摘要。
- LKM 必须记录目标内核、KMI、架构和产物摘要；Android 版本相同不代表 KMI 一致。

### UI 与交互

- 按主页、超级用户、模块、设置、主题、关于和导航分别审查，不将页面统一改造成同一种卡片布局。
- 覆盖浅色、深色、跟随系统、Material、Miuix、小屏、大字体、横竖屏和系统安全区。
- 检查加载、空列表、错误、无 Root、权限不足和操作失败状态。
- 检查悬浮底栏、普通底栏、模糊开关和壁纸叠加状态下的可读性与内容遮挡。
- 色彩对比度自动化测试是基础门槛，不替代真实设备的无障碍和视觉验收。

### 真机回归

在可恢复、已备份且内核匹配的测试设备上验证：

- Root / KernelSU 状态和版本读取。
- 新应用授权、允许、拒绝、撤销及重启后的授权状态。
- 模块列表、安装、启停、卸载和重启恢复。
- 设置持久化、主题切换、昼夜模式和 UI 模式切换。
- 壁纸选择、更换、恢复默认、重启后读取、提供方撤销权限和损坏图片回退。
- 安装、覆盖升级、签名身份和 LKM 配套关系。

没有真实设备结果的项目必须保持未验收，不得用代码审查或 CI 成功替代。

## 正式发布条件

- 自动化测试、Debug 构建和适用的 Lint 检查有明确记录。
- 正式 Release APK 使用既定 Application ID 和受控签名身份，且证书摘要与 LKM 信任配置一致。
- Root、授权、模块、设置、壁纸和升级链路完成目标设备回归。
- 许可证、上游来源、第三方素材授权和变更记录齐备。
- 未经明确授权，不创建正式 GitHub Release，不替换签名密钥或更改不可逆发布设置。

## 风险控制

- 不为了赶时间把失败的测试标记为通过。
- 不在无设备条件下宣称 Root、授权或模块功能已真机验证。
- 不擅自改变 applicationId、签名身份、KSU/LKM 授权协议或内核模块信任配置。
- 不提交 keystore、私钥、密码、令牌或包含个人信息的日志。
- 每个提交只包含经过审查的相关变更，并保留上游同步和回滚能力。
