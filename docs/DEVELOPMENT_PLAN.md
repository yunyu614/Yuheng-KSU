- [ ] 从上游确定可复现的源码基线，并记录仓库、分支、提交 SHA。
- [ ] 对照 KernelSU 官方与白饭参考项目，生成文件级差异清单。

- [ ] 首页改为 Root 状态与设备信息仪表盘。

## 阶段 4：验证与发布

- [ ] Gradle 编译与单元测试通过。
- [ ] 检查 APK 包名、签名、公钥与配套 LKM 兼容关系。
- [ ] 真机验证 Root 状态、授权、模块安装/启停/卸载及重启恢复。

- [ ] 发布源代码、许可证材料、变更记录和测试说明。

## 风险控制

- 不把“成功编译”当作 Root 功能通过验证。
- 不未经核验替换上游签名、公钥或 LKM。
- 不删除上游版权声明、许可证或贡献信息。
- 每个阶段先形成可构建提交，再继续扩大改动范围。
